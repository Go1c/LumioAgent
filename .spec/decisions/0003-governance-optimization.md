# 0003 · 治理优化：单一落点、审查不入库、lint 走 git 索引

- 日期:2026-09-01
- 状态:生效

## 背景

下游 LumioGameEngine 的治理复盘（PR #53 / #55）实证了框架的多处结构病：`docs/specs/`、`docs/plans/` 默认落点处于 lint 盲区并在下游长成并行文档根之一；设计稿定稿后靠人肉抄成 feature 文档（二次搬运必漂移）；审查文档成为决策散落的温床（两起未走 ADR 的裁决事故）；快速模式白名单声称机器可判却无脚本；每次会话强制注入的调度核心是「括号墙」。本轮以「框架自身合理性与完整性」为唯一标准（明确不以下游兼容为约束），核心尺子是第一性原理——如无必要，勿增实体。完整设计与波次见[治理优化 Roadmap](../plans/2026-09-01-governance-optimization.md)。

## 决策

1. **单一文档根**：框架产物（设计 / 计划）一律落 `.spec/`，废除 `docs/specs/`、`docs/plans/` 默认落点。弃案「保留 docs/ 并纳入校验」——下游实证盲区目录必腐，纳管一个不该存在的目录不如删除它。
2. **设计稿即 feature 文档初版**：brainstorming 直接写 `.spec/knowledge/features/`，终稿口吻 + `status: 设计中` 起步，流转到 `已交付`；讨论过程不入库，取舍进 ADR。弃案「设计稿独立成文、定稿后沉淀」——凡需人肉从 A 抄到 B 的制度，B 迟早是旧的。
3. **审查报告不入库**：活在交回物与 PR；决策留痕只有 ADR 一条路。弃案「建 `reviews/` + 裁决句式启发 lint」——多一个实体加一套防虫机制，不如温床不存在。
4. **lint 走 git 索引而非文件系统**：`git ls-files` 为遍历面，git-ignored 草稿（`.sdd/`）天然豁免。弃案「学下游改名 `.sdd-scratch/`」——改名治标，索引遍历治本。
5. **禁名 grep 替代技能足迹声明系统**：plugin-lint 拿禁名单 grep 插件资产正文。弃案「每技能声明文件足迹 + 交叉校验」——声明自身会漂移说谎，grep 抓的是正文实际写的路径。
6. **任务真值单轨**：宿主任务工具为日常真值，`.spec/tasks/` 只收跨会话必须存活的卡。弃案「维持双轨并称真值」——两本账必对不上，下游为此专设对账职能即是承认漂移为常态。
7. **lessons 错题本保留、升格机器不建**：错题本是「不配当规则的经验」的候待区（防规则膨胀），必要；「标签 + 引用计数 + 自动升格」流水线在错题本为空时属无必要增实体，升格走人工判断。
8. **`plans/` frontmatter 复用任务卡契约**（仅 `status`，同一枚举），不新增枚举实体。

## 后果

- **接受细则不常驻的遵守率风险**：注入面瘦身后（路由表 + 指针），细则靠按需加载；兜底是机器校验（lint / closeout-gate）而非条文在场。
- **接受审查报告不可追溯**：整体收口的审查结论只活在会话与 PR，仓内无档；换取的是决策散落温床的消失。
- **`docs/` 落点为 breaking change**：已按新制度换轨的项目与旧默认不兼容；换轨必须一次换完（规则、技能、模板、lint 同波落地），不留半轨——这正是下游「制度换了一半」教训的直接应用。
- `.sdd/` 名称保留，其「git-ignored 草稿」定位由公理二正名，无需防御性改名。
