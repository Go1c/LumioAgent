# 0004 · 产品 AI 能力的边界基线:不写库、可溯源、可关闭、外发受控

- 日期:2026-07-03(提炼自 GameFlow ai-explanations 的实践)
- 状态:生效

## 背景

产品内 AI 能力(摘要 / 解释 / 建议)如果一开始就直连外部 LLM,三类风险会同时敞开:AI 输出污染业务写路径、用户数据不受控外发、模型行为不可回归。实践证明先用**确定性实现**固化输入边界、来源引用、开关与「不写库」原则,再替换真模型,返工最少。

## 决策

- 四条基线进 `knowledge/standards/ai.md`,任何产品 AI 能力适用:**AI 永不直接写业务数据**(建议须人触发显式命令)、**输出可溯源**(source refs)、**可关闭且失败降级**(核心流不依赖 AI)、**外发受控**(显式配置 + 开关 + 权限边界内数据,作为 rules 外发禁令的唯一受控例外)。
- 密钥 write-only、prompt 版本化、限流、golden-set 评测是接真模型的前置条件。

## 后果

- 首版 AI 能力「不智能」(确定性模板)——换合同、测试、边界先稳定;接真模型成为纯适配器替换。
- 多一层端口抽象的成本,换厂商可替换与 dev 无 key 可跑。
