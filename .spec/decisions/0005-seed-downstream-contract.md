# 0005 · 种子↔下游契约:tag 发版、编号空间独立、回填走流程 D、冲突以下游为准

- 日期:2026-07-03
- 状态:生效

## 背景

种子与首个下游(GameFlow)并行演化数周后,两边已经出现:ADR 编号跨仓碰撞(同号不同题)、`.spec/tools/spec-lint.mjs` 双向分叉、回填全靠一次性人肉考古。「种子被复制后如何继续对话」没有任何成文契约,这对一个以被复制为目的的模板是结构性缺口。

## 决策

- **种子按 git tag 发版**(`vX.Y.Z`,变更写进 tag message);下游记录自己基于的种子版本。
- **ADR 编号空间各仓独立**:0001–0005 是框架 ADR,下游保留并从其后续号;跨仓引用写 `LumioAgent#NNNN`,不共享号段。
- **下游 → 种子的回填**走 `spec-steward`「流程 D」:准入 = 在至少一个下游真实项目验证过的**通用机制**;项目名词、技术栈绑定、业务规则不收。回填必须打新版本 tag。
- **种子 → 下游的更新**由下游对照 git tag / 提交历史人工吸收(见根 `README`);**冲突时以下游为准**——种子是起点不是上游依赖,不做强制升级。

## 后果

- 放弃「自动同步」的幻想,接受人工吸收的成本——换来下游本地化自由与种子极简。
- 版本 tag 成为新的维护义务;漏发版 = 下游失去吸收锚点。
