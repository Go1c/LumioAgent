# 0007 · 并行优先:契约先行拆解、统一合入后审一次、测试按任务大小分级

- 日期:2026-09-02
- 状态:生效

## 背景

原默认流程是 SDD 逐任务串行执行、每任务两级审查、每任务走 TDD。用户提出两条前提:一是尽可能并行开发——并行之前先把共同依赖(数据结构、类型定义、API、协议、通用模块、规范)拆解出来解除依赖,最后统一合并审查;二是小任务不要先走 TDD、减少用例与自动化跑次,大任务才需求聊清、TDD 先行。原流程的每任务审查与每卡跑全量与「快 > 稳 > 好」的调度取向不符。

## 决策

- **契约先行**:`writing-plans` 浅拆模式把共同依赖剥成 wave 0 契约卡,实现卡只通过契约卡的产物对齐;契约不足时改契约卡,实现卡不得私自扩接口。契约卡未合入不得扇出实现卡。
- **并行扇出、统一合入**:同一 wave 内文件集互不重叠的卡并行,各自独立 worktree;全部 wave 合入后再收口。
- **审查只在统一合入后做一次**:每卡 worker 只做 lint + 覆盖测试自检并交证据;reviewer 审整体 diff 一次。唯一例外是触碰红线面(`rules/`、hooks、`.claude/`、CI、鉴权 / 安全)的卡,合入前单审。
- **测试分级,阈值复用 `closeout-gate`**:纯文档 / 配置数据 / 注释 / 删除改动、或有效新增行 < 50 = 小任务,不要求先失败测试、不为每处改动加用例;其余 = 大任务,需求先经 `brainstorming` 聊清再 TDD 先行。红线面抬级只影响审查级别,不影响测试分级。修 bug 同此分级:小修复以复现步骤验证症状消失,大修复先写复现测试并留作回归。
- **跑次最少化**:worker 只跑覆盖本卡的测试,reviewer 不重跑,全量收口门槛只在统一合入后跑一次。

## 后果

- 放弃了每任务审查的早期拦截:一张卡的错误会在合入后才被审出,返工范围可能跨卡。用契约卡与文件集边界把这种返工限制在实现卡内部。
- 小任务免 TDD 意味着 50 行以下的行为改动可能没有新测试;由收口门槛的既有测试与 reviewer 的正确性维度兜底。
- 一套阈值同时决定审查级别与测试分级,改 `closeout-gate` 判定时两者同时变动,需在其头注释里维护。
