# Knowledge（项目知识库）

存放具体的、局部的项目知识，供 Agent 按需查阅。全局心智（四概念、渐进式披露）见 [`../AGENTS.md`](../AGENTS.md)。
每个子目录都有一个瘦 `README.md` 向导，顺着它一层层嵌套下钻即可。

## 下钻

- **standards** — 学科级详细规范（怎么做），稳定、要遵守 — [目录](./standards/) ｜ [README](./standards/README.md)
- **features** — 各功能的设计 / 过程 / 记录，演进、供了解 — [目录](./features/) ｜ [README](./features/README.md)

---

## 规范：本知识库怎么组织、怎么维护

### 缩放档位（L0 / L1 / L2）

项目知识是一道从全局到局部的缩放梯子。**别和“类型轴”混淆**：`L0/L1/L2` 是**作用域（缩放）**，而“总览 vs 约束 vs 规范 vs 记录”是**类型**，两根轴垂直。

- **L0 · 全项目**：项目总览（`AGENTS.md`）+ 全局护栏（`rules/`）。**已存在，知识库不重复造。**
- **L1 · 学科 / 模块**：学科级详细规范（`standards/`）、模块框架（`features/<领域>/`）。
- **L2 · 功能**：单个功能的设计 / 过程 / 记录（`features/<领域>/<模块>/<功能>.md`）。

### 两支结构

- **`standards/`（规范支）**：稳定、跨功能、**要遵守** → 按**学科**组织。
- **`features/`（功能支）**：具体、演进、**供了解** → 按**领域 → 模块 → 功能**组织（三级是上限，不是义务，内容薄就浅放）。

### 每个目录都有一个 README 向导（强制）

- 本目录下**每个子目录都必须有 `README.md`**。它是个**瘦路标**：只说“这目录是什么 + 有哪些子项 / 各自状态 + 子项的目录和 README 在哪”，**不装内容**（内容在叶子文档里）。
- Agent 顺着 README → 子 README **嵌套下钻**，这就是渐进式披露落到目录上的样子。
- 下钻条目格式：`- **<子项>** — <一句话：是什么 / 何时查> — 状态: <…> — [目录](./x/) ｜ [README](./x/README.md)`。

### Frontmatter（沿用 Skill 那套约定）

```yaml
---
name: <唯一名>                       # 通常与目录 / 文档同名
description: <一句话——是什么 / 何时查>  # 渐进式披露的发现钩子
metadata:
  type: index | doc                  # index = 目录向导 README；doc = 叶子内容文档
  level: L1 | L2                     # 缩放档位
  status: 设计中 | 已实现 | 已废弃     # 主要给 doc（功能文档）用
---
```

- 标准字段 `name` + `description` **必填**；扩展字段一律进 `metadata`（同 `skills/README.md` 第 2 节，不在顶层乱加）。
- **一句实话**：宿主**不会自动扫描** `knowledge/`（它只扫 `.claude/skills` 等约定目录）。这套 frontmatter 由我们自己读、自己维护，价值在于“统一格式 + 稳定的 description 钩子”。

### 维护

- **新增 / 删除任何知识文档或目录，必须同步更新所在目录 `README.md` 的下钻索引**——和「子 Agent 名册必须同步」同理。索引漂移 = 那篇知识对 Agent 隐身。
- 功能文档（L2）里可记“待解决 / 设计意图清单”，但**要执行的任务走 `planner` 任务卡**，别让知识库变成第二个任务队列。
- 具体“怎么新增 / 沉淀 / 同步”的操作流程见 `skills/spec-steward`。
