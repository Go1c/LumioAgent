# AI 能力接入规范(产品侧)

> 本文定**产品内 AI 能力**(面向用户的摘要 / 解释 / 建议 / 生成)如何接入模型的规范。研发 Agent 自身的协作规范在 [`AGENTS.md`](../../AGENTS.md),与本文无关。
> 这套边界提炼自实际项目经验:先用确定性实现固化边界与合同,再接真模型,返工最少。

## 1. 不可动摇的基线(适用一切 AI 能力)

- **AI 永不直接写业务数据**:不持有任何写端口;AI 建议进入写路径的唯一方式是**人触发已有显式命令**,由正常业务链路记账 / 审计。
- **输出必须可溯源**:每条摘要 / 建议 / 风险都带 source refs,能指回它依据的业务对象;解释是依据,不是事实写入。
- **可关闭**:AI 能力必须有开关(按产品的部署粒度——项目 / 工作区 / 租户);关闭只影响 AI 请求,核心业务流完全不依赖 AI 可用性。
- **失败降级**:AI 端点超时 / 报错不得阻塞或污染任何核心流程。

## 2. LLM 端口边界(接外部模型时)

- LLM 客户端走**统一端口**(接口在核心层,SDK / HTTP 细节在适配器层);必须有 dev stub 适配器,无 key 也能跑通全链路。
- 能用薄 HTTP 客户端就不引厂商重型 SDK。
- 外呼端点必须有 SSRF 防护(域白名单 + https + 拒内网 / 元数据 IP)。

## 3. 数据外发边界(`rules/system.md` 外发禁令的唯一受控例外)

数据离开部署环境去第三方 LLM 端点,必须**同时满足**:

1. 部署方**显式配置**了 LLM endpoint 与 key(默认无配置 = 功能不存在);
2. 目标范围的 AI 开关开启;
3. 进 prompt 的内容**只能**来自当前权限边界内的业务读模型。

**永远不得进 prompt**:密钥与凭据、个人敏感信息(邮箱 / 密码哈希 / session token)、越权数据、运维配置(webhook URL 等)。

## 4. 密钥 / prompt / 评测

- **密钥**:走环境变量 / 部署配置,write-only 范式(读接口只回「已配置」布尔,不回显);不入日志、不入事件流。
- **prompt 模板**:入仓库版本化,不散在代码字符串里;响应记录关联 model id + prompt 版本,可审计追溯。
- **速率 / 成本**:调用必须有限流;显式触发优先于自动触发。
- **评测**:接真实 LLM 前建 golden-set 回归(输入快照 → 期望输出要点);无评测不上线。
